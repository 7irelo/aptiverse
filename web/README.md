# Aptiverse web

The Aptiverse web app: Next.js 16 (App Router, React 19, Turbopack), Tailwind
CSS v4, shadcn/ui and a typed API client generated from the API's OpenAPI spec.

This is the Phase 1 "walking skeleton" from the rebuild plan. One real feature
runs end to end: the Help page at `/help` loads FAQs from the API on the
server and renders them grouped by category.

## Requirements

- Node 24 and npm 11
- The Aptiverse API running locally on `http://localhost:5100` (see the
  `aptiverse-labs/api` repo). The app still starts without it; the Help page
  then shows a friendly retry state.

## Run locally

```bash
npm ci
cp .env.example .env.local   # API_INTERNAL_URL=http://localhost:5100
npm run dev                  # http://localhost:3000
```

Open `http://localhost:3000/help` to see FAQs from the API.

## Scripts

| Script              | What it does                                                      |
| ------------------- | ----------------------------------------------------------------- |
| `npm run dev`       | Dev server with Turbopack                                         |
| `npm run build`     | Production build                                                  |
| `npm run start`     | Serve the production build                                        |
| `npm run lint`      | ESLint, including the house rules (tokens, Lucide, no emoji)      |
| `npm run typecheck` | Generates route types, then `tsc --noEmit`                        |
| `npm test`          | Vitest unit and component tests (MSW mocks the API)               |
| `npm run e2e`       | Playwright on Pixel 7, iPhone 14 and desktop Chrome, with axe     |
| `npm run format`    | Prettier                                                          |
| `npm run api:sync`  | Refresh `openapi/api-spec.json` from the API                      |
| `npm run api:gen`   | Regenerate `src/lib/api/generated` with Orval                     |
| `npm run api:check` | Regenerate and fail if the result differs from the committed code |

First time running E2E: `npx playwright install chromium webkit`. The suite
builds the app if no build exists, starts a small mock API
(`e2e/mock-api.mjs`) and runs against `next start`. After changing app code,
run `npm run build` before `npm run e2e` so the tests see your changes.

## The API contract

The client in `src/lib/api/generated` (types, zod schemas, TanStack Query
hooks) is generated by Orval from `openapi/api-spec.json`. Never edit it by
hand.

1. `npm run api:sync` copies the spec from `../api/openapi/v1.json` when the
   API repo is checked out next to this one, or downloads `API_SPEC_URL` (a
   pinned, versioned spec published by the API's CI).
2. `npm run api:gen` regenerates the client.
3. Commit both. CI runs `npm run api:check` and fails if they drift.

The committed spec is currently a hand-written seed with a single operation
(`GET /support/faqs`) so codegen works before the API publishes its own.

All requests go through one fetch wrapper, `src/lib/api/fetcher.ts`:

- On the server it calls `API_INTERNAL_URL` directly.
- In the browser it calls `/api/bff/...`, a thin proxy route
  (`src/app/api/bff/[...path]/route.ts`) that forwards to the API. Auth
  forwarding arrives in Phase 2.

## Design tokens

Graphite & Citron lives in `src/styles/tokens.css` as CSS variables and is
mapped into Tailwind in `src/app/globals.css`. Light and dark follow the
operating system (`prefers-color-scheme`). There is no theme toggle.

Fonts: the brand face, Frygia, has no font files in the old repo (it was
loaded from a third party CDN with an open licensing question). Until licensed
`.woff2` files are added to `src/fonts` and wired with `next/font/local`, the
system UI font stack is used.

## Security headers

`next.config.ts` sets a Content Security Policy, HSTS, `frame-ancestors
'none'` (plus `X-Frame-Options: DENY`), a strict referrer policy and a
permissions policy on every route. The CSP avoids nonces so marketing pages
stay static; moving to nonces is a later hardening step.

## Deployment

Vercel, pinned to Cape Town (`cpt1`) in `vercel.json`. Set these in the
Vercel project:

- `API_INTERNAL_URL`
- `NEXT_PUBLIC_APP_ENV`
- `NEXT_PUBLIC_SENTRY_DSN` (Sentry stays off while this is empty)
- `SENTRY_ORG`, `SENTRY_PROJECT`, `SENTRY_AUTH_TOKEN` for source maps

Vercel Analytics and Speed Insights are enabled in the root layout.

## Project layout

```
src/
  app/
    (marketing)/       public pages: home, help
    (auth)/            sign in and friends (placeholder until Phase 2)
    (app)/             signed-in area, Server Component layout (placeholder)
    api/bff/[...path]/ proxy for client-side API calls
  proxy.ts             request proxy, will guard (app) routes in Phase 2
  features/            one folder per domain (support, practice, ...)
  components/ui/       shadcn/ui primitives (owned code)
  components/shell/    header, footer, page states
  lib/api/             fetch wrapper and generated client
  lib/auth/            auth placeholder
  styles/tokens.css    design tokens
```
